# Daily Rehearsal

> 내일의 상황에 맞는 나를 미리 입어보고, 듣고, 말해보고, 티켓으로 가져가는 Daily Simulator

## 1. 프로젝트 정의

Daily Rehearsal은 전시장 방문자가 스마트 거울 앞에서 내일의 상황을 고르고, 짧게 브리핑하고, 내일의 모습을 입어본 뒤 AI와 몇 턴의 시뮬레이션을 진행하는 체험입니다.

이 프로젝트는 발표 코치나 면접 연습 앱이 아닙니다. 사용자가 내일의 상황을 미리 한 번 통과하고, 그 과정과 피드백을 티켓과 영상으로 가져가게 만드는 오프라인 Daily Simulator입니다.

핵심 컨셉은 “내일의 모드로 갈아입기”입니다.

## 2. 전체 플로우

```text
타입 선택
→ 브리핑성
→ 재질문 / 컨텍스트 수집
→ 옷 입히기
→ AI 시뮬레이션
→ 티켓 발급
```

관통 축은 세 가지입니다.

- 제스처 인식: MediaPipe 기반 공통 컴포넌트를 타입 선택과 옷 선택에서 재사용합니다.
- 세션 누적: 하나의 세션에 선택 타입, 브리핑, slot context, 의상, 대화 로그, 영상, 티켓 정보를 누적합니다.
- fallback: AI 또는 외부 API가 실패해도 화면이 멈추지 않도록 기본값과 고정 문구를 사용합니다.

## 3. 단계별 책임

### 1. 타입 선택

사용자는 제스처로 소개팅, 발표, 미팅 같은 `situationType`을 선택합니다.

프론트는 타입 선택 UI와 MediaPipe 제스처 인식을 담당합니다. 선택이 확정되면 세션을 시작합니다.

백엔드는 타입 리스트를 enum 또는 정적 매핑으로 제공합니다. 세션 생성 시 선택된 타입을 세션의 초기 context로 저장합니다.

### 2. 브리핑

선택된 타입에 맞는 고정 브리핑과 예시 답변을 보여줍니다.

프론트는 브리핑 표시와 다음 진행을 담당합니다. 백엔드는 타입별 브리핑 문구를 enum 또는 정적 매핑으로 제공합니다.

### 3. 재질문 / 컨텍스트 수집

사용자 발화는 프론트의 Web Speech API로 STT 처리하고, 변환된 텍스트만 백엔드로 보냅니다.

백엔드는 타입별 slot 정의를 기준으로 AI에 답변 정규화를 요청합니다. 한 답변에서 여러 slot이 채워질 수 있으며, AI 응답은 JSON으로 받습니다.

질문 문구는 enum에 고정합니다. AI는 답변 해석과 정규화만 담당합니다.

빈 slot이 있으면 백엔드는 빈 slot의 재질문을 리스트로 한 번에 반환합니다. `max_attempt`는 재질문 라운드 전체 횟수입니다. 초과하면 남은 빈 slot은 default로 채웁니다.

AI 호출 실패 시 해당 slot은 default로 처리하고 다음 화면으로 넘어갑니다.

### 4. 옷 입히기

백엔드는 선택된 타입과 `outfit_direction` context 값을 바탕으로 옷 후보 목록(`GET /outfits`)을 제공합니다. 프론트는 클라이언트 토큰(`POST /decart-token`)을 받아 WebRTC로 Decart에 직접 연결합니다.

첫 번째 옷은 자동으로 적용합니다. 사용자는 타입 선택과 같은 제스처 컴포넌트로 옷을 교체하고 선택합니다.

이 단계에서 프론트 MediaRecorder 녹화를 시작합니다. 녹화는 옷 입히기부터 시뮬레이션 종료까지 이어집니다.

최우선 기술 검증은 Decart WebRTC track이 MediaRecorder로 녹화 가능한지입니다. 이 전제가 깨지면 6번 티켓의 영상 제공 방식이 바뀝니다.

### 5. AI 시뮬레이션

시뮬레이션은 타입과 누적 context를 기반으로 AI 상대와 대화합니다. 턴 수는 `N`으로 고정합니다.

각 턴은 AI 호출을 두 번으로 나눕니다.

1. 판정 + 피드백 API: 사용자 발화를 받아 성공/실패와 피드백을 JSON으로 동기 응답합니다.
2. 다음 발화 SSE API: 다음 상대 발화만 순수 텍스트로 토큰 스트리밍합니다.

프론트는 피드백 영역과 다음 발화 영역을 분리합니다. 1차 결과를 먼저 표시하고, 2차 발화는 아래나 다음 영역에 흐르듯 표시합니다.

성공하면 다음 턴으로 넘어갑니다. 실패하면 같은 턴을 재시도합니다. 재시도 횟수는 제한하지 않고, `N`턴에 도달하면 종료합니다.

LLM은 stateless로 보고 매 호출마다 전체 대화 히스토리를 전달합니다. `N`이 작기 때문에 별도 memory 시스템은 두지 않습니다.

AI 실패 시 fallback은 다음과 같습니다.

- 1차 실패: “다시 시도해보세요” 피드백으로 실패 처리
- 2차 실패: 상황별 고정 상대 발화 사용

SSE의 목적은 속도 향상이 아니라 토큰 스트리밍 연출과 체감 지연 감소입니다.

### 6. 티켓 발급

프론트는 MediaRecorder 녹화를 종료하고 영상을 백엔드가 제공한 업로드 경로로 업로드합니다.

백엔드는 누적 context, 의상, 대화 로그, 피드백, 영상 URL을 묶어 티켓을 생성합니다. QR은 다운로드 페이지 URL을 인코딩합니다.

사용자가 QR을 스캔하면 모바일 다운로드 페이지에서 영상과 티켓을 받을 수 있습니다.

## 4. 기술 역할

| 기술 | 역할 |
| --- | --- |
| MediaPipe | 타입 선택과 옷 선택에 쓰는 공통 제스처 인식 |
| Web Speech API | 사용자 발화를 프론트에서 transcript로 확정 |
| Decart WebRTC | 선택한 옷을 입은 내일의 모습 preview |
| MediaRecorder | 옷 입히기부터 시뮬레이션까지 연속 녹화 |
| Gemini | slot 정규화, 시뮬레이션 판정/피드백, 다음 상대 발화 생성, 티켓 문구 생성 |
| SSE | 다음 상대 발화의 토큰 스트리밍 연출 |
| Storage | 영상과 티켓 다운로드 페이지 저장 |
| QR | 다운로드 페이지 URL 전달 |

## 5. 현재 결정 사항

- Daily Rehearsal은 전시장용 단일 플로우입니다.
- 세션에 `channel` 개념은 두지 않습니다.
- slot 질문 문구와 default는 enum/정적 매핑으로 관리합니다.
- AI provider는 Gemini 하나만 사용합니다.
- AI는 답변 해석, 정규화, 시뮬레이션 판정, 다음 발화 생성, 티켓 문구 생성을 담당합니다.
- 하나의 세션에 context, 의상, 대화 로그, 영상, 티켓 정보를 누적합니다.
- AI 실패 시 default 또는 고정 문구로 처리해 시연이 멈추지 않게 합니다.
- 백엔드는 클라이언트 토큰과 옷 스펙(prompt/referenceImageUrl)만 제공하고, 프론트가 WebRTC로 Decart에 직접 연결합니다.
- 녹화는 프론트 MediaRecorder에서 처리하고, 백엔드는 외부 접근 가능한 영상 URL을 확보합니다.
- 티켓 QR은 다운로드 페이지 URL을 담습니다.
