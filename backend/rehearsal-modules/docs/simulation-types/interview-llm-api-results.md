## 결과 해석

### 잘 동작한 부분

1. 브리핑에서 사용자가 걱정하는 면접 주제를 `critical_moment`로 잘 추출했다.
2. 2턴은 1턴의 성공한 답변에 있던 프로젝트, 협업, 사용자 개선 표현을 이어받았다.
3. 3턴은 2턴 답변의 세부 내용을 다시 묻는 꼬리질문으로 생성됐다.
4. 질문과 무관하거나 회피하는 답변은 `RETRY_REQUIRED`로 분류했다.
5. 재시도 답변이 정상적이면 다음 턴은 재시도에서 성공한 내용을 이어받았다.

### 튀닝이 필요한 부분

1. 사례 3의 3턴 `RECOVERY` 질문은 2턴 질문을 거의 그대로 반복했다. 현재 recovery 지시가 "질문을 더 작고 쉽게 분해한다"는 것을 강제하지 못하고 있다.
2. recovery에서는 직전 질문을 문자열로 반복하지 말고, "문제 상황 하나만 말해보세요" → "그때 본인이 한 행동을 말해보세요"처럼 작은 단계로 바꾸는 규칙이 필요하다.
3. 평가 피드백은 전반적으로 자연스럽지만 `ACCEPTED`일 때는 칭찬 비중이 높다. 다음 답변에 바로 적용할 수 있는 개선점 한 가지를 함께 주도록 튀닝할 수 있다.
4. 실패 시 두 번째 평가의 세부 피드백은 `FORCED_ADVANCE` 고정 문구로 덮어써진다. 티켓이나 최종 피드백에 실패 원인을 활용하려면 raw AI feedback을 별도로 보존할지 검토해야 한다.
