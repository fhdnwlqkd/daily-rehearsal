# 면접 Gemini 회귀 실험 6: 전시 입력 경계와 행동 안내 계약

## 1. 목적

실제 전시장에서 발생할 수 있는 짧고 불친절한 발화, 안내 문구 복창, 배경 음성, 불성실하지만 질문에는 답한 발화를 실제 Gemini API로 검증했다. 또한 화면의 `actionPrompt`와 내부 평가 기준인 `acceptedIntentHint`가 동일한 답변 요소를 요구하는지 확인했다.

- 모델: `gemini-3.5-flash-lite`
- thinking budget: `-1`
- 저장소: 실험별 독립 MySQL schema
- 검증 방식: 실제 REST API, RDB polling, 실제 Gemini worker

## 2. 전체 결과

| 범주 | 검증 수 | 결과 |
|---|---:|---|
| 정보가 거의 없는 브리핑 | 5 | 5/5 follow-up 진입 후 흐름 완료 |
| 무례하지만 질문에 답한 발화 | 5 | 5/5 `ACCEPTED` |
| 거부·비속어·무관한 발화 | 5 | 5/5 `RETRY_REQUIRED` |
| 행동 안내 복창·빈칸 읽기 | 5 | 5/5 기대 판정 |
| 배경 음성이 합쳐진 발화 | 5 | 5/5 기대 판정 |
| 범용 면접 주제의 2·3턴 생성 | 5 | 10개 행동 안내 생성 성공 |
| 화면 안내와 내부 합격 기준 일치 | 10쌍 | 10/10 의미상 일치 |

실험 중 Gemini 호출 실패나 worker `FAILED`는 발생하지 않았다.

## 3. 불친절한 답변의 처리

질문 의도에는 답했다면 표현이 아쉬워도 흐름을 멈추지 않았다.

| 입력 요약 | 판정 | feedback 방향 |
|---|---|---|
| `뭐 별건 없고요...` | `ACCEPTED` | 정중한 어조 하나만 코칭 |
| `저는 끝까지 설득할 겁니다` | `ACCEPTED` | 경청과 조율 태도 코칭 |
| `따질 겁니다` | `ACCEPTED` | 공격적 표현을 정중한 표현으로 교정 |
| `진상 고객은...` | `ACCEPTED` | `화가 나신 고객님`으로 용어만 교정 |

반면 답변 거부, 면접관에게 역질문하기, 무관한 발화, 비속어는 5/5 모두 재시도로 분류했다. 따라서 “품질이 낮은 답변”과 “답변이 아닌 발화”의 경계는 유지됐다.

## 4. 행동 안내 복창과 배경 음성

- `actionPrompt`를 그대로 읽기, 빈칸을 두고 읽기, `이제 답변하겠습니다`처럼 예고만 하기는 모두 `RETRY_REQUIRED`였다.
- 짧아도 실제 자기 내용을 채운 답변 2개는 모두 `ACCEPTED`였다.
- 완결된 핵심 답변 앞뒤에 짧은 배경 발화가 붙은 3개는 통과했고, 배경 발화만 있거나 답변이 중간에 끊긴 2개는 재시도했다.

이 결과는 LLM의 문맥 판단이며 화자 분리가 아니다. 다른 사람의 정답 발화가 함께 들어오는 경우는 프론트 STT/VAD 단의 보완이 필요하다.

## 5. `actionPrompt`와 합격 기준 정렬

초기 개선본에서는 화면이 `첫 행동과 이유`를 요구하지만, 내부 `acceptedIntentHint`는 `첫 행동`만 검사하는 불일치가 있었다. 사용자에게 더 어려운 요구를 보이고 서버는 더 낮은 기준으로 평가하는 계약 문제였다.

생성 규칙을 다음과 같이 보강했다.

1. turn objective가 복수 요소를 명시하지 않으면 최소 답변 요소 하나만 요구한다.
2. objective가 행동이나 입장만 묻는데 이유·예시·결과를 임의로 추가하지 않는다.
3. `acceptedIntentHint`는 `actionPrompt`와 동일한 요소만 요구한다.
4. 모범 답안, 빈칸, 플레이스홀더는 제공하지 않는다.

재실험에서 생성된 10쌍은 모두 일치했다.

| 화면 행동 안내 | 내부 최소 합격 기준 |
|---|---|
| `동료와 의견이 다를 때 취할 첫 행동을 한 문장으로 말해보세요.` | `동료와 의견이 다를 때의 첫 행동을 말한다.` |
| `상대의 의견을 먼저 듣는 이유를 한 문장으로 말해보세요.` | `상대의 의견을 먼저 듣는 이유를 말한다.` |
| `화난 고객을 마주했을 때의 첫 행동을 한 문장으로 말해보세요.` | `화난 고객을 마주했을 때의 첫 행동을 말한다.` |
| `지원하게 된 이유를 한두 문장으로 간단히 말해보세요.` | `회사에 지원한 이유를 한 가지 이상 말한다.` |

## 6. 남은 한계와 후속 검토

1. `면접이요`, `긴장돼요`처럼 아주 짧은 브리핑은 follow-up을 해도 개인화 slot이 null로 남을 수 있다. 현재는 `maxFollowUpAttempt=1` 후 범용 면접으로 진행하는 정책이다.
2. 후속 질문이 여러 주제에서 `이유나 판단 기준`으로 수렴하는 경향은 줄었지만 남아 있다.
3. LLM 출력은 확률적이므로, 운영 중 완전한 계약 보장이 필요하면 생성 결과의 요구 요소를 서버에서 구조적으로 검증하고 재생성하는 보호장치가 필요하다.
4. 배경 음성 오탐은 prompt만으로 없앨 수 없으므로 프론트 STT 종료점과 화자 분리 검토가 남아 있다.

## 7. 결론

현재 면접 흐름은 짧고 불완전한 전시 발화와 명백한 실패를 구분했고, 불친절하지만 유효한 답변을 지나치게 막지 않았다. 행동 안내 복창과 배경 음성 경계도 준비된 10개 예시에서 의도대로 동작했다. 마지막으로 화면이 요구하는 답변과 실제 평가 기준의 계약도 10/10으로 정렬됐다.
